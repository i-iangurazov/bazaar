# Поиск и создание товаров по фото: китайские открытые проекты

Исследование от 14 ноября 2026 года. Основание: пользователь отказался от платных посреднических API и потребовал изучить китайские исходники до выбора реализации. Поиск должен быть бесплатной функцией Bazaar для организаций всех тарифов; существующие права на просмотр и создание товаров сохраняются. Расходы сервера и уже используемого DeepSeek нельзя представлять как нулевые.

**Последующее уточнение:** первый выпуск ищет товары внутри выбранного магазина Bazaar; китайские предложения — будущий этап. До реализации подготовлена [архитектура внутреннего поиска и создания товара по фото](product-photo-workflows-architecture.md). Приоритет проверки прямого 1688 ниже в этом документе отражает предыдущую постановку и больше не определяет первый выпуск.

Это проверка документации и конкретных исходных модулей. Чужой код не устанавливался и не исполнялся, ключи не получались, аккаунты не регистрировались, запросы поиска не отправлялись. Наличие репозитория не является подтверждением работоспособности на нашем аккаунте или разрешения использовать сервис во всех организациях Bazaar.

## Главный результат

Есть готовые китайские реализации трёх разных частей задачи:

1. Поиск настоящих предложений через шлюз самого 1688 либо через браузер пользователя. Свой алгоритм сопоставления фотографий для этого не нужен.
2. Самостоятельное сравнение изображений по собственной индексированной базе: PP-ShiTu/PaddleClas и Chinese-CLIP. Это готовые модели и готовые механизмы поиска, без обучения с нуля.
3. Превращение фотографий и исходных материалов в карточку/черновик товара: пример процесса есть в `next-1688`, а возможности анализа фотографий DeepSeek уже используются в Bazaar.

HioBuy не является обязательным компонентом ни одного из этих направлений. Открытая модель сравнения изображений сама по себе не предоставляет каталог 1688, цены и ссылки: источник предложений нужно подключать отдельно.

## 1. Прямой поиск: next-1688/1688-product-find

[Репозиторий](https://github.com/next-1688/1688-product-find), исследованный commit `2c7d8ee014ec24c730e5ddc966c70f2495891543`.

Прочитаны `cli.py`, `scripts/_http.py`, `_auth.py`, `_image.py`, `settings.py`, `scripts/capabilities/image_search/service.py` и описание интерфейса.

**Как устроено:**

- Изображение приводится к JPEG, ограничивается размером 800 × 800; исходный файл допускается до 5 MiB.
- Локальный снимок передаётся base64, также предусмотрен URL.
- `image_search/service.py` собирает `imgBase64`/`imageUrl`, `pageSize`, параметры релевантности и фильтры, затем вызывает общий поиск.
- `_http.py` отправляет запрос на `https://gateway.1688.com/api/alibaba.1688.find.product/1.0.0/github`. Это домен 1688, а не HioBuy/TMAPI/OneBound.
- Нормализуются идентификатор, название, изображение, исходная ссылка, цена, продавец, минимальное количество и другие поля. У некоторых записей есть оценка сходства.
- `_auth.py` содержит AK-подпись и OAuth: авторизация на `air.1688.com`, получение, обновление и отзыв токенов через шлюз 1688. AK предлагается получать через `clawhub.1688.com`.

**Что брать для Bazaar:** понимание настоящего протокола поиска, параметров изображений, формата ответа и жизненного цикла авторизации. Наши существующие загрузка/HEIC/JPEG, проверка файлов и карточки результатов уже подходят для такой интеграции.

**Что не установлено:** разрешён ли собственный серверный клиент Bazaar, какой клиент OAuth допустим для нас, кто должен авторизоваться, применимы ли ограничения по региону/сценарию, какие квоты и стоимость. В GitHub metadata этого репозитория нет определённой лицензии; публичность кода не даёт оснований копировать его целиком. Схему интеграции можно исследовать, условия доступа и повторного использования нужно установить до включения.

Первичный адрес `clawhub.1688.com` ответил HTTP 200 на проверку доступности из локальной среды; это не проверка авторизации или поиска. Данные методов найдены в коде, а не получены реальным вызовом.

Связанный [1688-shopkeeper](https://github.com/next-1688/1688-shopkeeper/blob/main/README.md) объясняет получение AK в приложении 1688 AI. В его FAQ подбор и размещение названы **бесплатными на ограниченный период**, с отсылкой к правилам 1688. Это не гарантия постоянной бесплатности `product-find` и не лицензия на наш SaaS.

## 2. Поиск в браузере: yifan4243-sketch/1688_claw-skill

[Репозиторий](https://github.com/yifan4243-sketch/1688_claw-skill), commit `4a8c3dc884ec74e42068c9f32ecbcf6ead3f899d`. Код — MIT; лицензия прочитана. Node.js/TypeScript, Playwright; опубликована версия 0.1.1.

Прочитаны README, package.json, `packages/adapters-1688/src/client.ts` и `engine/commands/image-search.ts`.

**Как устроено:** открывается штатная страница поиска 1688, изображение выбирается через file chooser, из адреса результата извлекается `imageId`, затем собираются предложения со страницы выдачи. В браузере используется собственный авторизованный профиль. Клиент дополнительно умеет получать подробности кандидатов. По README проект предназначен для сбора данных и не создаёт заказов/платежей; при проверке/ограничении требуется вмешательство пользователя.

**Что можно переиспользовать:** адаптер результатов, разделение поиска и подробностей, обработку недействительной сессии, отдельные профили, восстановление после ошибок. Оплата посреднического API в этой реализации не требуется.

**Ограничения для Bazaar:** это локальный CLI, а не готовый облачный поиск для мобильного браузера. Чтобы сохранить логин у пользователя, потребуется расширение/локальный помощник либо другой согласованный способ связи с его браузером. Капча, изменения страницы и лимиты могут прерывать работу. MIT разрешает использование кода, но не заменяет условия сайта. Централизованную общую сессию 1688 для всех клиентов Bazaar не использовать. Проект не проверялся на надёжность реальными поисками, не является готовой производственной зависимостью.

## 3. Собственный визуальный поиск: PaddleClas / PP-ShiTuV2

[Репозиторий PaddlePaddle/PaddleClas](https://github.com/PaddlePaddle/PaddleClas), ветка `release/2.6`, исследованный commit `202ac79a99aa368f2c95cb1871bbc11574f685da`. Код Apache-2.0.

Прочитаны китайский README, quick start распознавания, `deploy/python/predict_system.py`, документация `vector_search.md` и `gallery_manager.md`.

**Готовый процесс:** выделить товар на фотографии → вычислить признаки готовой моделью → найти похожие изображения через Faiss. Есть построение и обновление базы, порог совпадения, top-K, CPU-поиск, примеры товаров и мобильная демонстрация. Это уже готовый механизм, а не предложение обучить собственную нейросеть.

**Применимость:** найти такой товар в ассортименте своей организации, обнаружить вероятный дубль перед созданием карточки, подобрать похожие позиции. База формируется из разрешённых изображений Product/ProductImage. Индексы должны быть изолированы по организации; ассортимент магазина и доступ пользователя проверяются до выдачи. Отсутствие в индексе не означает отсутствие товара в Китае.

До внедрения нужны небольшой стенд на реальных типах товаров Bazaar, оценка CPU/RAM/времени индексации, корректное удаление/архивирование записей и проверка условий выбранных весов. Пригодность готового кода не означает, что Paddle следует включать в основной Next.js-процесс: вероятнее нужен отдельный локальный сервис/worker, решение принимается после измерения.

## 4. Альтернатива модели: OFA-Sys/Chinese-CLIP

[Репозиторий](https://github.com/OFA-Sys/Chinese-CLIP), commit `31863c707501bf1605d36842f43deb78793dbc5d`, MIT по GitHub metadata. Прочитан README с использованием готовых моделей, извлечением признаков и сравнением изображения/китайского текста.

Подходит как кандидат для сопоставления фото, китайских названий и собственного каталога. Важен для подбора товаров по сочетанию визуального сходства и текста. Не предоставляет каталог китайских площадок. Выбор между ним и PP-ShiTu требует сравнения на одних товарах; одновременно внедрять оба без измерения не нужно.

## 5. Фото → черновик: next-1688/1688-product-1688-product-manage

[Репозиторий](https://github.com/next-1688/1688-product-1688-product-manage), commit `fa31af26479e8d80cad596aa0ed3195739c93bc2`. Прочитано описание процесса `SKILL.md` как исходный материал, без установки или исполнения. Этот пример работает в окружении Accio/Ali1688 и сохраняет черновик на 1688; готовым серверным модулем Bazaar он не является.

Процесс уже соответствует замыслу пользователя: собрать фотографии/текст/ссылки по отдельным товарам → определить категорию и характеристики → подготовить заголовок и варианты → сохранить проверяемый черновик. Отдельно предусмотрены неизвестные поля и возобновление прерванной операции. Отсутствующие цены/остатки не подменяются выдуманными значениями.

Для Bazaar полезен сам порядок действий и обработка пробелов в данных. Вместо чужих инструментов публикации использовать наш `product-form`, существующие схемы создания товара, проверку прав/магазина и DeepSeek. Из фотографии можно предложить видимое название, категорию, цвет, текст упаковки и описание. Закупочную/продажную цену, остаток и скрытые характеристики модель не определяет как факт. Создание карточки не должно автоматически создавать остатки или закупку; сохранение должно быть идемпотентным и показывать происхождение предложенных значений.

## 6. Что уже есть в Bazaar и DeepSeek

В Bazaar проверены `src/server/services/aiProvider.ts`, `productSpecSuggestions.ts`, `productDescriptions.ts`, `productImageStudio.ts` и связанные точки `product-form.tsx` / products router. Есть общий DeepSeek Responses-клиент, согласие на передачу фото, бюджетирование, предложения характеристик, описания и анализ изображения. Нужна сборка полного пользовательского процесса создания, а не новая интеграция LLM с нуля.

В актуальной [документации DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/) модель `deepseek-flash` принимает изображения. В [Web Tools](https://api-docs.deepseek.com/guides/web_tools/) описан также поиск по изображению при входящем фото. Такой поиск относится к веб-поиску: он не гарантирует полноту каталога 1688 или подтверждённые цены. Web/image-search инструменты оплачиваются отдельно от токенов, поэтому их нельзя автоматически включать под обещанием нулевых расходов. Это возможный кандидат для испытания с уже используемым DeepSeek, без нового посредника, а не доказанная бесплатная замена API площадок.

## Решение для следующего прототипа

- Бесплатная функция для пользователей всех тарифов, с сохранением ролевых прав и изоляции организаций. Коммерческий gate `marketplaces`, введённый в HioBuy-прототипе, противоречит уточнению пользователя и должен быть удалён в следующем изменении. Сейчас этот gate ещё есть; этот документ не сообщает о его исправлении.
- Приоритет для настоящих предложений 1688 — прямой путь из `1688-product-find`: установить разрешённый способ доступа и условия аккаунта, затем проверить несколько реальных фото. Без подтверждения не обещать бесплатный безлимит.
- Браузерный MIT-проект — отдельный возможный вариант с пользовательской сессией, прежде всего для настольной версии. Не подменять им незаметно серверный мобильный поиск.
- Для поиска по собственному ассортименту — испытать готовый PP-ShiTu; Chinese-CLIP оставить альтернативой. Не начинать обучение собственной модели или сбор всего каталога 1688.
- Для создания товара по фото — существующий DeepSeek и наш редактор с предложенными полями, проверкой обязательных данных и подтверждением сохранения. Эта часть не обязана ждать доступа к китайскому маркетплейсу.
- Taobao, Pinduoduo и Poizon подключать независимыми адаптерами фактических источников. Поддержка нижестоящих магазинов Pinduoduo/Taobao в `1688-shopkeeper` означает размещение товаров из 1688, а не поиск по фотографии во всех этих площадках.

## Что проверено и что осталось

Проверены конкретные исходники, адреса назначения, формат загрузки и ответа, базовые лицензии, зависимости и разница между локальным браузером и серверным API. Приведены снимки commit для повторного изучения. Основной сайт Bazaar, тарифы и runtime-код этой работой не изменяются; исторический провайдерный отчёт помечен как заменённое направление.

Не проверены авторизованный ответ 1688, условия его бесплатного доступа для Bazaar, региональная регистрация, разрешение на SaaS, точность/скорость моделей на нашем ассортименте и аппаратная съёмка. Эти неопределённости относятся к конкретным испытаниям и доступу, а не требуют разработки алгоритма поиска с нуля.
