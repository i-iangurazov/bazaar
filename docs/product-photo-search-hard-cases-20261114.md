# Проверка похожих товаров и обновление интерфейса

14 ноября 2026. Ветка `codex/playground`, только локальная среда.

## Как справляется с похожими товарами

Выполнено два разных испытания. Результаты не заменяют проверку SKU магазина и не
являются обещанием точности на ассортименте Bazaar.

**Повторный анализ открытого стенда.** Из 200 контрольных идентичностей ALOI выбраны
20 непересекающихся пар, наиболее близких по признакам **галереи** `r0/r90`.
Контрольные снимки не использовались для подбора пар или изменения порога. У каждой из
40 идентичностей — пять отдельных снимков: ракурсы `r30/r60/r180`, свет `l3c1`, температура
`i120`. Поиск остаётся по полной галерее из 300 предметов / 600 фотографий.
Использованы ранее измеренные, сохранённые признаки настоящей PP-ShiTuV2; хеши manifest
и файла признаков сверяются с опубликованным протоколом исходного стенда.

| На сложной части, 200 отдельных снимков | Результат |
| --- | ---: |
| Правильный предмет на первом месте до отсечения | 193 / 200 (96,5%) |
| Правильный предмет среди первых пяти до отсечения | 197 / 200 (98,5%) |
| Правильный предмет виден в первых пяти при пороге 0,68 | 186 / 200 (93,0%) |
| Неверный первый кандидат проходит порог | 3 / 200 (1,5%) |
| Если убрать нужный товар: остаётся похожий кандидат выше порога | 117 / 200 (58,5%) |

В общей контрольной части прежние 99% Recall@5 относятся к ранжированию **до порога**.
При действующем пороге правильный товар виден в первой пятёрке в 916 из 1000 запросов,
а для отсутствующих предметов похожий кандидат появляется в 29 из 180 случаев.
Поэтому 99% нельзя использовать как показатель точности готового пользовательского
сценария или как гарантию определения артикула.

**Новый запуск настоящей службы.** Проверены шесть пар / 12 предметов: кружки с разными
рисунками, банки с разными этикетками, фигурки, консервные банки, зелёные блоки разной
высоты и прямоугольные предметы. Они выбраны по фотографиям галереи, без подбора успешных
контрольных запросов. Всего 24 фотографии галереи и 60 отдельных запросов.
Запущен отдельный экземпляр текущей PP-ShiTuV2 + Faiss на loopback 3161 с одноразовым
токеном; снимки проходят ту же подготовку Sharp, что и в Bazaar. Клиентская БД и
запущенный пользователем поисковый сервис не менялись.

| Настоящий текущий runtime, 60 снимков | Результат |
| --- | ---: |
| Правильный предмет на первом месте | 58 / 60 (96,7%) |
| Правильный предмет виден среди первых пяти после порога | 53 / 60 (88,3%) |
| Неверный первый кандидат проходит порог | 1 / 60 (1,7%) |
| При исключении нужного товара остаётся похожий кандидат | 25 / 60 (41,7%) |

Одинаковая фотография с двумя разными артикулами возвращает **два кандидата с одинаковым
сходством**. Это отдельный проверяемый случай неоднозначности, а не независимые снимки
для расчёта точности. В протокольном тесте также проверено, что 12 записей признаков одного товара не
вытесняют второй товар из выдачи и что выдача ограничена восемью разными товарами.

Практическое решение: ручной выбор сохраняется. Сходство не показывается как вероятность
верного SKU. Для нескольких кандидатов добавлена подсказка проверить модель, цвет,
размер и артикул. Порог не менялся по этим контрольным результатам. Поиск ранжирует
карточки Product; отдельные варианты внутри одной карточки здесь не оценивались.

Ограничения: ALOI — фотографии предметов 154×115 px в лабораторных условиях, не реальные
торговые упаковки в шумном магазине. Изменения цвета, мелкий текст и варианты ELFBAR
пока не проверены на нескольких настоящих устройствах. Перекрашенные изображения
и искусственные ракурсы в показатели точности не включались. Пользовательский снимок
со стола не сохранён, поэтому сообщённый пользователем успех не включён в числовую оценку.

## Что изменилось в интерфейсе

На desktop снимок и действия расположены рядом с визуальной сеткой кандидатов. На
телефоне окно открывается снизу; крупные фотографии результатов можно сравнивать
рядом. Выбор — отдельная кнопка с локализованным именем; нажатие на обычное название
не открывает карточку и не выбирает первый результат автоматически.

Добавлены короткое появление карточек и обратная связь во время реального поиска.
Процентная шкала используется только для фактически обработанных фото каталога;
время поиска и уверенность не симулируются. Минимальная искусственная задержка отсутствует.
CSS-анимации учитывают `prefers-reduced-motion`. Снимок сохраняется в окне после ошибки;
отмена, повтор, неполный поиск и смена организации/магазина продолжают работать.

Основа решений:

- [Ant Design / Ant Group: Motion](https://ant.design/docs/spec/motion/) — короткая,
  обоснованная обратная связь и простые переходы.
- [Google Lens: визуальный поиск товаров](https://blog.google/products-and-platforms/products/shopping/visual-search-lens-shopping/)
  — снимок/загрузка и просмотр визуальных кандидатов с данными товара.
- [Alibaba Image Search: image query](https://www.alibabacloud.com/help/en/image-search/user-guide/search-for-images)
  — разделение исходного снимка, области предмета и поиска. Ручное выделение области
  рассматривается как следующий шаг; в текущем интерфейсе такой возможности нет.

Платные сервисы этих компаний не подключались. Использованы существующие компоненты
Bazaar, локальная модель и CSS; новая библиотека анимаций не добавлялась.

## Ошибки консоли

Воспроизведён `TRPCClientError: featureLockedBundles`: обычная карточка запрашивала
`bundles.listComponents` сразу после открытия, включая STARTER. Теперь запрос выполняется
для комплекта или после явного открытия соответствующих действий. Права сервера
не ослаблены; чтение настоящих комплектов и ручное управление ими сохраняются.

При переходе к выбранному товару также воспроизведено предупреждение Next.js о
`scroll-behavior: smooth`. Для существующего CSS добавлен рекомендованный
[атрибут корневого html](https://nextjs.org/docs/messages/missing-data-scroll-behavior).

В старом серверном логе имеется `MaxListenersExceededWarning`. После чистого старта с
`--trace-warnings` при повторных поисках и переходах оно пока не воспроизвелось; причины
старого предупреждения без стека не установлены. Лимит обработчиков не увеличивался
для скрытия сообщения. Это ограничение диагностики, а не подтверждённое исправление.

товаров по магазинам, UI, транспорт запросов и роли. Данные ручного стенда на 55991

с изолированными локальными настройками; развёртывание не выполнялось.

После проверок дополнительная среда на 55981/55982 остановлена. Ручной магазин,
обработчик фотографий, модель и Wi-Fi preview на 3158 оставлены работающими.

В браузере вручную проверены каталог и касса с настоящим локальным поиском: две
похожие кружки, выбор второго кандидата и возврат к сравнению. Desktop-окно полностью
помещается в экран; на размере 390×844 нет горизонтального переполнения, доступны
обе карточки и кнопки выбора. Обычное нажатие на название не выполняет переход.
После чистого старта и перехода из карточки в каталог новых ошибок и предупреждений
консоли не зарегистрировано; в кассе после поиска и выбора — также.
Для автоматического браузерного сценария добавлены проверки границ окна и отсутствия
запроса комплектов у обычного товара; этот сценарий в данном проходе не запускался,
выполнена проверка его синтаксиса и описанная ручная проверка через браузер.

Для ручного сравнения в тестовый магазин добавлены пять явно помеченных открытых товаров:
две кружки, банка с другой этикеткой, два зелёных блока. Исходный ELFBAR сохранён.
Фотографии других ракурсов лежат в `.local/product-photo-search/try-photos/lookalikes`.
