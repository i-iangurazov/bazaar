# Журнал улучшений bazaar в playground

Ветка: `codex/playground`. Основа: свежий `origin/main` на момент создания, `6aadb6c8947b82df7632fdd0ef4d82eddbd72e47`, 21 октября 2026 года. Вливание в `main` и production-публикация требуют явного указания владельца. Рабочие правила сохранены в корневом `AGENTS.md`.

Основной CI запускается и на push в `codex/playground`, поэтому будущие пакеты проходят существующие unit/integration, браузерные, native и release-gate проверки до общего вливания. Сам workflow CI не публикует приложение.

## Тарифы и доступ к прогнозам

Пакет исправляет подтверждённые противоречия тарифа STARTER и недостаточную проверку магазина в прогнозе. Денежные списания в этом пакете не подключаются.

- Касса открыта на STARTER, включая активный пробный период, в соответствии с обещанием «Новичка». Цены 1750/4375/8750 KGS и существующие лимиты 1/5/15 магазинов, 1000/5000/20000 товаров и 5/10/20 активных пользователей сохранены. Остальные права тарифов и ручное одобрение не изменены.
- Лендинг, структурированные предложения и кабинет используют один серверный каталог. Серверный override цены отражается везде без потери дробной части. В сравнении перечислены все модули, включая заказы клиентов и ценники.
- Добавлены локализованные публичные тарифы RU/KG/EN. В английском кабинете исправлены заглушки названий, цены, заявки и ограничений.
- Прогноз проверяет назначение пользователя магазину до чтения товара и движений. Сохранён разрешённый доступ всех прежних ролей; администратор/владелец не получает доступа к другой организации. Отзыв назначения учитывается следующим запросом.
- Обновлены актуальные таблицы тарифов в README и документации. Исторический аудит сохранён отдельно как снимок исходного коммита.

## Проверки пакета

Целевые проверки включают реальную продажу через POS на STARTER с уменьшением остатка и повтором того же запроса, сохранение закрытых дополнительных модулей, лимитов и уже одобренного доступа. Прогноз проверяется на синтетическом контексте и настоящих записях отдельной PostgreSQL, включая чужой магазин, другую организацию, разрешённый магазин и отзыв grant.

Браузерный сценарий `scripts/qa/playground-pricing-browser.ts` работает только с явно указанной локальной QA-базой, проверяет production bundle, публичное сравнение и кабинет в 390/1440 px на RU/KG/EN, а также доступ кассира STARTER к POS. `scripts/qa/playground-runtime.mjs` удаляет провайдерские настройки из окружения и запрещает production-миграции. Полный DB-набор использует другую одноразовую базу, поэтому его сбросы не затрагивают браузерные фикстуры.

Временные снимки исходников/QA-артефакты исключены из обнаружения Vitest и server file tracing. Для браузерной проверки запускается `.next/standalone/server.js` с упакованными static/public, а не dev-сервер. Используются только синтетические сессии и данные; реальный вход, регистрация мерчанта и работа платёжного провайдера этим сценарием не проверяются.

Первый общий прогон обнаружил зависимость существующих тестовых фикстур от timezone/locale PostgreSQL: одноразовый кластер был создан с C locale и Asia/Bishkek. На точном исходном `main` удалось воспроизвести те же сбои; после пересоздания тестовых БД с UTC и en_US.UTF-8 все 41 проверки из восьми затронутых наборов прошли без изменения бизнес-кода. Финальный общий прогон выполняется в этом корректном окружении. Это не изменение бизнес-часового пояса Bazaar.

Старые standalone-файлы очищаются перед QA-сборкой; `.next` также исключён из обнаружения тестов. Проверка существующего лендинга учитывает локализованный формат цены, включая английский разделитель тысяч. Финальные сырые отчёты относятся к завершённым успешным прогонам; промежуточные сбои не считаются пройденными.

Сводка и хеши проверенных исходников: [playground-verification-2026-10-21.json](playground-verification-2026-10-21.json). Последний CI исходного `main` на базовом SHA также [успешен](https://github.com/i-iangurazov/bazaar/actions/runs/39428527837). CI для готового коммита playground отслеживается отдельно в GitHub Actions; локальная проверка не выдаётся за результат удалённого CI. Production не публиковался, внешние провайдеры не проверялись.

Для повторения production UI-проверки нужны подготовленная локальная PostgreSQL со схемой проекта (пользователь `bazaar_test`, база `bazaar_hardening_agent4_platform`) и отдельный Redis DB 1. Передать их URL через `PLAYGROUND_DATABASE_URL` / `PLAYGROUND_REDIS_URL`, выполнить `node scripts/qa/playground-runtime.mjs build`, затем `node scripts/qa/playground-runtime.mjs serve`. В отдельном терминале запустить `NODE_ENV=test VERCEL_ENV=development node --import tsx scripts/qa/playground-pricing-browser.ts` с тем же `PLAYGROUND_DATABASE_URL`. Отчёт, скриншоты и сырые логи сохраняются в игнорируемый `tmp/playground-verification/`. Сервер необходимо остановить после проверки. Скрипты намеренно отклоняют обычную/удалённую базу.

По исходному backlog этот пакет закрывает B01 и B19, а для B02 проверяет основную продажу через POS в STARTER trial. Весь onboarding и будущая модель платной подписки не объявляются завершёнными.
