# Linux-проверка фотопоиска — 15 ноября 2026

Настоящие PP-ShiTu, PicoDet, PP-OCRv6 medium и Faiss успешно запущены в отдельной
тестовой Linux-среде GitHub Actions. Платные API, клиентские базы и production не
использовались. Это проверка совместимости службы, а не новая оценка точности каталога.

Первое успешное выполнение: [CI 43633353792, product-photo-linux](https://github.com/i-iangurazov/bazaar/actions/runs/43633353792/job/132564676457),
commit `32788641b06175babe0c0e474584e2e9a98cb901`.
[Полный результат](benchmarks/product-photo-linux-20261115/result.json) и
[15 тестов службы](benchmarks/product-photo-linux-20261115/unit.txt) сохранены рядом.
Архив GitHub Actions `product-photo-linux` дополнительно содержит build/runtime logs.

## Среда и границы

Runner Ubuntu 24.04, контейнер Debian bookworm / glibc 2.36 / x86_64,
CPython 3.13.18. Версии моделей и главных библиотек сохранены: PaddlePaddle 3.3.1,
Faiss 1.16.0, RapidOCR 3.9.2, ONNX Runtime 1.29.0. Все 31 Python wheel закреплены по
версиям и SHA256 в Linux lockfile. Системные зависимости OpenCV входят в образ.
Модели скачиваются и проверяются по хэшам только при сборке.

Сам поиск выполняется без сети (`--network none`), от пользователя `bazaar`, с корнем
только для чтения и без портов/БД хоста. Разрешены только ограниченные временные файлы
и публичные проверенные фотографии в read-only mount. Ключ синтетический и создаётся
на время теста. После проверки собственные контейнер и временные фотографии удаляются;
образ в registry не публикуется. Локальный ручной магазин остаётся без изменений.

Контейнер ограничен 2 CPU и 4 GiB. Выборочный контроль максимума памяти cgroup показал
936 MiB; полный запрос с 10 000 нормализованными векторами — около 631 мс. Это не
оценка производственной пропускной способности: большая матрица использует повторённый
реальный вектор, а не независимые 10 000 SKU. Поток, OCR и конкурентность проверены
отдельно; нагрузку реальных магазинов всё равно нужно оценивать в целевой среде.

## Реальные фото и проверки

12 публичных фотографий по закреплённым хэшам: четыре отдельных запроса, восемь
эталонов. Включены естественные снимки Banana и Arla Lactose Medium Fat Milk из
закреплённого GroceryStoreDataset и два ракурса двух предметов ALOI. Файлы фотографий
не добавляются в git или CI artifacts.

Все четыре запроса получили правильного первого соседа в этой небольшой галерее.
Время запросов с выделением/OCR: 1,22; 3,48; 1,45; 1,37 с. На упаковке молока
распознано 11 строк; работа OCR проверена фактически, а не только наличием импорта.
Из этих четырёх кадров нельзя делать вывод о широкой точности и отсутствующих товарах:
для этого остаётся [отдельный широкий тест](product-photo-wide-20261115.md).

Успешно проверены:

- HTTP 401 без ключа; 400 для испорченного изображения, матрицы, области, порога и флага.
- Нормализация настоящего 512-мерного embedding, ручная и автоматическая области.
- Замена галереи между запросами: результат не содержит индексов предыдущей области.
- 10 000 векторов, не больше восьми кандидатов, соблюдение времени ответа адаптера.
- Шесть одновременных запросов: один 200, остальные пять 429, без неконтролируемой очереди.
- Незаконченная передача тела запроса: сервер прерывает чтение через 10,01 с,
  освобождает обработчик и успешно обслуживает следующий поиск.
- Принудительное падение только собственного дочернего Faiss: health обнаруживает
  отказ, первый запрос получает 503, следующий успешно выполняется после перезапуска.
- SIGTERM с кодом завершения 0, повторный старт и готовность; OOM не было.

Все 15 существующих Python-тестов службы также прошли внутри Linux-контейнера.
Изоляция организаций/магазинов и актуальные цены проверяются на уровне Bazaar в
отдельных PostgreSQL-тестах CI; приватная Python-служба не хранит каталог организаций.

## CI и подготовка к main

Job `product-photo-linux` добавлен в обязательные зависимости `release-gate`.
Ошибка или пропуск job не дают зелёного итогового gate. Полный CI текущего SHA
проверяет также безопасность зависимостей, CodeQL, реальные DB-тесты, каталог
10 000 товаров / 100 000 цен, stabilization, браузерные сценарии, Android/iOS,
контейнер WhatsApp worker и production build. Итог всего CI нужно смотреть на
последнем коммите рабочей ветки, а не переносить успех Linux-job на весь набор.

Первый полный прогон выявил отставшие условия тестов: синтетические пользователи
BAAM не имели теперь обязательного согласия на передачу данных AI. В тестовых фикстурах
явно задано согласие для предусмотренных сценариев и добавлена проверка его отзыва;
серверный контроль сохранён. В landing-проверке устранена гонка измерения уже удалённого
при hydration скрытого Radix select: измеряется текущий DOM одним снимком, прежние
строгие требования к реально присутствующим контролам сохранены.

Повтор обнаружил также задержанный mount поля ввода BAAM после чтения согласия:
первоначальный проход автофокуса успевал закончиться раньше появления поля.
Composer теперь восстанавливает ожидающий фокус при появлении, сохраняя осознанно
перемещённый фокус на другой контрол. Добавлены проверки позднего mount и сохранения
выбора пользователя; 52 теста composer/launcher/consent прошли локально, как и типы,
lint и проверка переводов. UI-матрица повторяется в полном CI.

В сценарии вложений BAAM задан отдельный публичный синтетический ключ тестового
шифрования, который никогда не берётся из пользовательской среды. Browser regression
проверяет актуальный контракт: вложение приватно, без авторизации возвращает 401,
при подтверждённом создании товара получается отдельный файл организации с теми же
байтами, а исходное вложение остаётся зашифрованным. Дополнительно учтён эквивалентный
computed overflow `clip` у скрытого native select в Chromium; все проверки 1px,
нулевой clipping rect, запрета фокуса и доступности остаются обязательными.

Автоматический Vercel Preview отдельно останавливается на проверке среды:
`DATABASE_URL is required in production` (Next build использует production mode и
для Preview). Проверен именно deployment с `environment=Preview` и
`production_environment=false`. Рабочая БД к нему не подключалась, конфигурация
Vercel не менялась. Это не результат Linux-job или production deployment:
тестовая инфраструктура этого этапа — временные изолированные сервисы GitHub Actions.

Ветка готовится к ревью целиком, с учётом ранее накопленных улучшений. Слияние в main,
автоматическое слияние, настройка production-сервиса, публикация контейнера, изменение
рабочих секретов и production deployment в эту работу не входят.
