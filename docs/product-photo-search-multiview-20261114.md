Последующий [разбор девяти пропусков](product-photo-search-misses-20261114.md)
сохраняет эти исходные измерения и отдельно проверяет новые изменения.

В последнем прогоне остальные **9/14** однозначных входов дали пустую выдачу.
Неверных первых карточек здесь не было, но высокая доля пропусков не позволяет
считать различение вкусов решённым. Порог визуального сходства сохранён **0,68**.
Чтение надписи не подтвердило ни одного ответа этого полевого набора.

Три отдельных кадра с несколькими предметами: до изменения 3 пустых ответа;
после — нужная карточка первой на одном кадре Sakura Grape `660 с`, два пустых.
Это не однозначная идентификация выбранного пользователем предмета в общей сцене.
Три кадра отсутствующего Baja Splash остались пустыми в обоих режимах во всех версиях.

Сравниваются **20 изображений, по 40 парных запросов** в каждом прогоне, а не
120 независимых фотографий. Исходный прогон сохранён из предыдущего изменения,
две новые версии проверены настоящим авторизованным API Bazaar и локальными моделями.
Файлы запросов, ручные области, маркировка и канонизованные байты одинаковы во всех
трёх запусках; это проверяет [агрегатор](../scripts/qa/summarize-elfbar-multiview.mjs).

**Это проверка известных случаев после разработки, не независимая оценка точности.**
Галерея и запросы взяты из разных кадров тех же роликов, иногда близких по времени.
Новые независимые съёмки ассортиментных товаров телефонами клиентов ещё нужны.

## Что изменено в алгоритме

В прежней обработке отбрасывались детекции ниже 0,5 и предметы меньше 3% кадра.
Если два объекта имели близкую уверенность, оставался весь кадр. Устройство могло
проиграть руке/человеку ещё до сравнения с ассортиментом.

Использован подход из официальных исходников PaddleClas, без нового поискового движка:

- [Конфигурация 202ac79](https://github.com/PaddlePaddle/PaddleClas/blob/202ac79a99aa368f2c95cb1871bbc11574f685da/deploy/configs/inference_general.yaml)
  задаёт порог детектора 0,2 и максимум пять областей.
- [SystemPredictor.predict](https://github.com/PaddlePaddle/PaddleClas/blob/202ac79a99aa368f2c95cb1871bbc11574f685da/deploy/python/predict_system.py)
  распознаёт предложенные области и полный кадр, затем использует сходство.

В Bazaar полный кадр и до пяти областей кодируются PP-ShiTuV2; Faiss получает их
**одним пакетом** с одной текущей разрешённой матрицей магазина. Кандидаты объединяются
по товару и максимальному сходству. Лучшая область выбирается для рамки и одного
вызова RapidOCR; уверенность детектора в руке не определяет выбор товара.
Крошечные/невалидные прямоугольники отбрасываются по реальным пикселям и границам.

Ручная рамка по-прежнему использует только выбранную область; отключённое
автовыделение — только полный снимок. Ошибка детектора оставляет полный кадр.
Не менялись кодировщик, его веса/версия признаков, тарифы, Node API, порог выдачи,
правила сопоставления надписи и обязательный выбор кандидата пользователем.

На прежней галерее вернулись три ранее пропущенных однозначных кадра:
Watermelon Cherry `40 с`, Strawberry Banana `290/320 с`. Дополнительный ракурс
дал ещё один — Strawberry Banana `210 с`, дисплей. Все шесть непустых автоматических
ответов последнего прогона имеют настоящую автоматически выбранную область.

## Дополнительные фотографии

Через существующие загрузку изображения и `products.update` с `imagesOnly` добавлено
**девять** изображений к трём тестовым карточкам, по три на товар. Прежние эталоны
сохранены; новые фронтальные снимки стали главными только у этих трёх карточек.

| Товар | Источник 1080p, временные отметки | Виды |
| --- | --- | --- |
| Watermelon Cherry | [Андрей Фурманович](https://www.youtube.com/watch?v=qChbS3VN888), 120/60/90 с | Спереди, дисплей, сзади |
| Strawberry Banana | [Clube do Vaping Backup, репост](https://www.youtube.com/watch?v=q7v-Bj1Kzh8), 170/200/255 с | Спереди, дисплей, дисплей под углом |
| Sakura Grape | Тот же ролик, 640/550/575 с | Спереди, наклон, сторона дисплея под углом; часть корпуса закрыта рукой |

Это реальные вырезки из исходников 1920×1080, без увеличения разрешения нейросетью,
генерации, дорисовки, перекрашивания или изменения освещения. Размеры вырезок и SHA-256
зафиксированы в [манифесте](../scripts/qa/fixtures/elfbar-photo-multiview.json).
Ни один проверочный временной момент не индексируется. Фронтальные эталоны используют
прежние моменты с более качественным исходником; остальные ракурсы — другие моменты.

Для Sakura Grape доступный материал всё ещё недостаточно чистый: рука закрывает
название и корпус, есть смаз. Он не называется студийной фотографией и не выдаётся
за полноценную съёмку всех сторон. Для Strawberry Banana нет чистого заднего эталона.
Результаты не отделяют эффект разрешения от эффекта дополнительных ракурсов.
Прежняя неполнота матрицы вкусов/условий, включая тёмные сцены Grape Ice и отсутствие
новых независимых кадров Pineapple/Peach, сохраняется.

Медиа остаются в игнорируемом `.local/elfbar-multiview`, в git только происхождение,
контрольные суммы и ответы. Права на публичное/production-использование этих медиа
данным локальным испытанием не устанавливаются.

## Изоляция и стоимость

Изменены только изображения трёх карточек магазина `photo-search-field-shop`
в явно одноразовой локальной БД на 55991. Их цены, остатки и другие бизнес-поля
сравнены до/после; исходные изображения/идентификаторы сохранены. Повторный `augment`
не изменил ни одной карточки; 36/36 признаков готовы, ошибок и ожидания нет.
Исходный магазин, включая пользовательский Miami Mint, не изменился:
SHA-256 состояния `e9a24c6013287569b2df3cf6cbb13e194971b3d18313a76ed0127d003a487f4b`.

Все результаты повторно проверены на принадлежность магазину/организации;
пустой контрольный магазин не получил кандидатов. Нет общего индекса магазинов,
постоянного кэша запросов или сохранения поисковых снимков. Бесплатный доступ на всех
тарифах сохранён; CPU/хранилище собственного сервера всё равно потребляют ресурсы.
Подписок и внешних вызовов для распознавания нет. Существующие авторизация, повторная
проверка доступа, лимиты, тайм-ауты, один активный расчёт и восстановление Faiss сохранены.

Последовательное локальное время API: автоматический режим, медиана 458 → 613 → 612 мс;
p95 1288 → 748 → 832 мс. Ручной режим последней версии: медиана 282, p95 434 мс.
Слишком маленькая выборка и неконтролируемый фон; это не доказательство ускорения,
оценка пропускной способности или измерение production-сервера.

## Воспроизведение

Нужна уже подготовленная ручная изолированная среда из
[README службы](../services/product-photo-search/README.md). Для регрессии БД используется
**другая** одноразовая инфраструктура 55981/55982; не сбрасывайте ручную среду 55991.

Публичные оригиналы скачаны отдельно из источников манифеста с `yt-dlp==2026.10.26`
(выбор `bestvideo[ext=mp4][height<=1080]`), FFmpeg из `imageio-ffmpeg==0.8.1`.
Подготовка не скачивает медиа и не меняет манифест при несовпавшем хэше:

```sh
node scripts/qa/prepare-elfbar-multiview.mjs --ffmpeg=/absolute/path/to/ffmpeg
node scripts/qa/product-photo-search-field.mjs verify --multiview
# При прежней галерее 27 фото, ДО augment:
node scripts/qa/product-photo-search-field.mjs evaluate --run=detector-v2
node scripts/qa/product-photo-search-field.mjs augment --multiview
node scripts/qa/product-photo-search-field.mjs evaluate --multiview --run=multiview-v2
node scripts/qa/product-photo-search-elfbar.mjs evaluate --vision --run=multiview-v2
node scripts/benchmarks/product-photo/runtime-hard-cases.mjs --vision --run=multiview-v2
node scripts/qa/summarize-elfbar-multiview.mjs
```

Для API нужны локальные `PRODUCT_PHOTO_QA_BASE_URL`, `PRODUCT_PHOTO_QA_EMAIL`,
`PRODUCT_PHOTO_QA_PASSWORD`. Runner допускает только фиксированные локальные
адрес/порт/БД/пользователя/маркер и QA-организацию. Паузы/Retry-After соблюдают
настоящие ограничения запросов; Redis не сбрасывается. Снимки каталога/признаков
до и после каждого прогона совпадают.

Ответы: [прежняя версия](benchmarks/product-photo-field-20261114/results.json),
[новое выделение](benchmarks/product-photo-multiview-20261114/detector-results.json),
[новая галерея](benchmarks/product-photo-multiview-20261114/multiview-results.json),
[агрегаты](benchmarks/product-photo-multiview-20261114/summary.json).

  Четыре отсутствующих вкуса по-прежнему дают визуальных соседей с неподтверждённым
  текстом; их нельзя считать правильной идентификацией. Наличие Sakura в другом
  тестовом магазине не изменило этот отрицательный контроль.
- [ALOI, 60 входов](benchmarks/product-photo-multiview-20261114/aloi-results.json):
