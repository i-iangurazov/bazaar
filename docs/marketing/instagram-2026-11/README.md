## Путь обращения и атрибуция

1. Ссылка ведёт на существующий локализованный лендинг. На нём есть регистрация и WhatsApp `+996 709 911 300` для обсуждения подключения. Не требуется новая форма со сбором телефона.
2. `/signup` запрашивает фактический режим: `open` показывает создание учётной записи; `invite_only` — заявку на доступ с email и необязательным названием организации. При ошибке режим не предполагается, есть повторная загрузка.
3. Открытая регистрация создаёт пользователя, затем предлагает создать бизнес и первый магазин. Создание пользователя и завершённая регистрация бизнеса — разные показатели. Возобновление не перезаписывает первоначальный источник.
4. UTM первого размеченного перехода сохраняется на 30 дней в first-party HttpOnly cookie. Это непроверенная метка источника, а не доказательство рекламного клика. Источник сохраняется сервером только при успешной записи заявки или нового пользователя. Полный URL, fbclid, идентификаторы Meta и содержимое переписки не записываются. Допустимы короткие ASCII-метки без личных данных. DNT и GPC отключают сбор.
5. Cookie работает на корневом лендинге и `/signup`; локализованный URL сначала перенаправляется с сохранением меток. Нет отслеживания внутренних рабочих маршрутов, витрин покупателей, показов контента или переходов между устройствами. Удаление cookie, другой браузер и отказ от отслеживания дают неатрибутированный результат, который нельзя искусственно присваивать Instagram.
6. Direct связывается с материалом по ключевому слову и ответу человека; только отправленное сообщение считается обращением. На обычном WhatsApp лендинга UTM не переносится: спросите источник, отметьте как `self_reported` и не выдавайте за доказанную рекламную конверсию. Не объединяйте разные бизнесы по одному имени.

Добавлена nullable-миграция `20261103120000_signup_attribution` для `User.signupAttribution` и `AccessRequest.signupAttribution`. Она не меняет тарифы, счета, склад и доступы. Политика конфиденциальности обновлена на RU/KG/EN. Развёртывание этой миграции и кода в production — отдельное действие, здесь оно не выполнялось. До релиза UTM-ссылки открывают текущий сайт, но новая серверная атрибуция на нём ещё не работает. Отчёт SQL в `attribution-report.sql` выполняется владельцем с разрешённым доступом только после релиза.

## Обработка заявок

Владелец BAZAAR отвечает на входящие в два удобных окна в день, например 12:00 и 18:00. Это внутренний режим работы, не публичный SLA. Короткий первый ответ:

«Здравствуйте! Спасибо за интерес к BAZAAR. Подскажите, пожалуйста, город, что продаёте и сколько у вас магазинов. Что хотите решить в первую очередь: касса, остатки или отчёты? Можем согласовать время показа.»

Кыргызская версия:

«Саламатсызбы! BAZAAR'га кызыкканыңыз үчүн рахмат. Кайсы шаардасыз, эмне сатасыз жана канча дүкөнүңүз бар? Биринчи кайсы маселени чечкиңиз келет: касса, калдыктар же отчёттор? Көрсөтүү убактысын макулдашсак болот.»

Квалифицированная заявка: реальный розничный бизнес в Кыргызстане, отвечает владелец или человек, участвующий в решении; названа задача, понятен масштаб и согласован следующий шаг. Не требуйте личные или платёжные документы для квалификации. Запрос цены без контекста — обращение, но пока не квалифицированная заявка. Не вводите жёсткий срок покупки как фильтр, отмечайте готовность отдельно.

После показа отправьте по договорённости одну ссылку для следующего шага. Один повторный контакт допустим только если человек согласился на него; после отказа прекращайте. Не отправляйте массовые Direct, автокомментарии и подписки. Не покупайте аудиторию и не собирайте чужие контакты парсингом. ИИ готовит черновик ответа, человек проверяет сведения и отправляет.

Вход для ИИ — актуальные разрешённые возможности и тарифы, частые обезличенные вопросы и итоги прошлой недели. Контентные файлы находятся в репозитории; контакты и разговоры клиентов — в отдельном закрытом учёте владельца.

Последовательность: идея → черновик текста → проверка обещаний → выпуск изображений и видео → просмотр владельцем → согласовано → передано планировщику → подтверждено размещение → проверены обращения. Согласование относится к конкретному тексту и контрольным суммам файлов. Изменение материала отменяет пригодность старого согласования. ИИ не утверждает собственные материалы от имени владельца.

Команды из корня репозитория:

```sh
node scripts/marketing/instagram/prepare.mjs
FFMPEG_BIN=/absolute/path/to/ffmpeg node scripts/marketing/instagram/ingest.mjs /private/path/canva-exports.json
node scripts/marketing/instagram/review.mjs
node scripts/marketing/instagram/workflow.mjs review
node scripts/marketing/instagram/workflow.mjs approve p02_ru REVIEWED_HASH OWNER_NAME
node scripts/marketing/instagram/workflow.mjs export
```

`prepare.mjs` создаёт 18 RU-заданий текущей редакции, подписи, ссылки и SRT. Изображения и видео не генерируются. `ingest.mjs` принимает локальные финальные экспорты Canva и номера исходных дизайнов; он читает метаданные и копирует файлы, не меняя изображение. Reels проверяются как 1080×1920 и 20 секунд, рекламные видео — 1080×1920 и 15 секунд; файл полностью декодируется FFmpeg. Пример схемы входа для одной полной карусели (пути иллюстративные):

```json
{
  "packages": [
    {
      "originalId": "p02",
      "locale": "ru",
      "canvaDesignIds": ["DAHZ1lf4spg"],
      "frames": [
        "/private/exports/p02-1.png",
        "/private/exports/p02-2.png",
        "/private/exports/p02-3.png",
        "/private/exports/p02-4.png"
      ],
      "stories": [
        "/private/exports/p02-story-1.png",
        "/private/exports/p02-story-2.png",
        "/private/exports/p02-story-3.png"
      ]
    }
  ]
}
```

Для Reels дополнительно нужны `video` — абсолютный путь к готовому MP4, `cover` — отдельная обложка 4:5 не меньше 1080×1350 и `coverTool` (`imagegen` или `canva`). Для рекламной концепции текущей редакции нужны три `frames` 4:5, три `verticalFrames` 9:16 и `video` на 15 секунд; для дня только Stories — пустой `frames` и три `stories`. При отсутствии кадров, неправильном размере или недекодируемом видео импорт завершается ошибкой без записи нового пакета.

`approved-queue.json` содержит только полные согласованные органические материалы со стабильными ключами повторов. Изменение задания, текста или файла требует повторного импорта и проверки. Это передача на ручное планирование, а не подтверждение размещения. Реклама этим путём не экспортируется даже при подставленном согласовании. До согласования конкретных файлов экспорт возвращает пустую очередь; сейчас согласовано 0 пакетов. Скрипты согласования не дают разрешение на внешнюю публикацию, которую владелец отключил.

При подключённом Metricool или Meta Business Suite: сначала подтвердите личный браузерный профиль, точный @bazaar.pos, права на публикацию и доступные форматы. Затем передавайте только согласованную языковую версию, дату, подпись и файлы. После сохранения прочитайте ID и состояние записи. При таймауте сначала ищите запись в планировщике по дате и материалу; не нажимайте повторно публикацию вслепую. Ведите закрытый журнал `idempotencyKey → remotePostId → scheduled/published/failed`, а «published» подтверждайте ссылкой на реальный материал. Не храните токены в репозитории и не просите секреты в чате.

Если Stories со ссылкой нельзя отправить через выбранный планировщик, подготовьте файл и добавьте стикер вручную в Instagram. Не публикуйте картинку с обещанием ссылки без работающей ссылки. Если соединение отозвано или материал отклонён, очередь остаётся на паузе; исправьте причину и повторно согласуйте изменённый материал. После публикации проверяйте обрезку текста, правильность языка, ссылку и доступность формы с телефона. При существенной ошибке уберите материал из расписания и согласуйте исправление.

Официальные ориентиры: [Meta for Business о планировании](https://www.youtube.com/watch?v=PQjvbXyMhkM), [документация Instagram API от Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api). API предназначен для профессиональных аккаунтов; возможности Stories отличаются по типу аккаунта. Точный доступ проверяется в подключённом аккаунте. В этой поставке собственный Meta API-клиент не создаётся: без подтверждённых прав и аккаунта его нельзя проверить.

## Учёт результата

В закрытом журнале храните один идентификатор бизнеса, источник и достоверность источника, материал, дату обращения, задачу, город, число точек, квалификацию с причиной, следующий шаг, проведённый показ, ID зарегистрированной организации и подтверждение подписки. Согласие на повторный контакт и отказ отмечаются отдельно. Контактные данные не коммитятся и не передаются ИИ для генерации публикаций.

Основные числа: уникальные обращения, квалифицированные бизнесы, проведённые показы, завершённые регистрации организаций и подтверждённые подписки. Стоимость квалифицированной заявки = фактический рекламный расход / уникальные квалифицированные заявки из платного источника. Стоимость регистрации = расход / зарегистрированные организации из платного источника. Media CAC = расход / подтверждённые новые платящие бизнесы. Общий CAC дополнительно учитывает фактические расходы на контент и продажи. Для органики фиксируйте затраченное время: отсутствие медиарасхода не означает нулевую полную стоимость.

Не объединяйте органические регистрации с рекламным знаменателем. Не считайте повторную заявку, повторное создание токена, приглашение сотрудника и второго владельца отдельными привлечёнными бизнесами. Не суммируйте количества по материалам без дедупликации. Запись заявки и регистрация одного бизнеса — этапы одной воронки. «Подписка подтверждена» ставится только по разрешённому учёту поддержки и финансовому подтверждению, не по обещанию оплаты и не по ответу ИИ.

Команда `node scripts/marketing/instagram/report.mjs /private/path/metrics.json` считает показатели из проверенных записей. Она не подключена к Meta, WhatsApp и CRM и не собирает информацию самостоятельно. Вход:

```json
{ "currency": "KGS", "spend": [], "events": [] }
```

Расход: `campaign`, `content`, `amount`. Событие: `campaign`, `content`, `medium` (`organic_social`, `paid_social` или `unknown`), `kind` (`lead`, `qualified`, `demo`, `registration`, `subscription`), `entityId` (устойчивый внутренний ID бизнеса), `evidence` (ссылка или ID подтверждения в закрытом учёте). Кампания — `kg_store_launch_202611`. Персональные данные в этот файл не нужны. Передавайте затраты и события одного периода; поздние регистрации отмечайте как конверсию исходной когорты, не сравнивайте расход одной недели с результатом другой без пояснения.

В дни 7 и 14 просмотрите квалификацию и результат по материалам и языкам. Если просмотры есть, а переходов нет — проверьте понятность предложения и CTA. Если есть переходы без заявок — проверьте форму, язык и соответствие обещания тарифу. Если обращаются неподходящие бизнесы — уточните аудиторию и формулировку. Если показы проходят без регистрации — соберите причины отказа. На малой выборке не объявляйте победителя по одному обращению.
