## Как включить готовые страницы без изменения кода

Отдельная серверная переменная `BAZAAR_PUBLIC_LEGAL_NAME` публикует только явно согласованное юридическое имя владельца в подвале лендинга на RU/KG/EN. Она не копирует приватные `BILLING_SELLER_*`, адрес, ИНН или банковские реквизиты и не открывает четыре юридические страницы. Значение задаётся в окружении после отдельного разрешения владельца; персональные данные не добавляются в исходный код или переводы.

Подтверждённые личные реквизиты хранятся только в серверном окружении, а не в публичном репозитории. `src/server/legal/seller.ts` читает разрешённые имена переменных, перечисленные ниже. В `src/content/legal/seller.ts` для личных полей стоят `null`; публично оставлены только согласованные телефон/email и обозначение KGS. Значения не добавлять в `.env.example`, JSON переводов, тесты, Markdown репозитория или `NEXT_PUBLIC_*`.

После заполнения реквизитов `src/lib/legalPublication.ts` дополнительно проверяет одновременно три серверные настройки:

- `BILLING_LEGAL_RELEASE_APPROVED=2026-11-07-v1` — явное утверждение именно этой редакции после окончательной юридической проверки и согласования с провайдером.
- `BILLING_SUPPORT_EMAIL_VERIFIED=1` — только после настройки и проверки приёма обращений на `support@bazaar.kg`.
- `BILLING_PUBLIC_CONTACT_ADDRESS` — реальный, согласованный полный адрес для корреспонденции. Пустой адрес, один город и очевидные заглушки не проходят проверку. Это не разрешение выдумать адрес: FreedomPay должен письменно подтвердить допустимый вариант для ИП без офиса, а применимые правовые требования должны быть проверены.

Только после заполнения всех обязательных серверных реквизитов, задания этих трёх настроек и обновления окружения страницы отображают утверждённую редакцию без черновых предупреждений и пустых полей; общий футер лендинга получает четыре ссылки. Если хотя бы одного условия нет, страницы возвращают 404, ссылки остаются закрыты. Адрес регистрации остаётся `null`; загрузчика домашнего адреса нет. Ошибочно включённый локальный preview в production не обходит проверку.

Серверные имена реквизитов без значений:

```text
BILLING_SELLER_LEGAL_NAME
BILLING_SELLER_ENTREPRENEUR_NAME
BILLING_SELLER_TAX_ID
BILLING_SELLER_REGISTRATION_NUMBER
BILLING_SELLER_REGISTRATION_DATE
BILLING_SELLER_REGISTRATION_AUTHORITY
BILLING_SELLER_PHONE
BILLING_SELLER_EMAIL
BILLING_SELLER_BANK_NAME
BILLING_SELLER_BENEFICIARY
BILLING_SELLER_ACCOUNT_NUMBER
BILLING_SELLER_ACCOUNT_CURRENCY
BILLING_SELLER_BANK_CODE
```

Локально эти поля заполнены из частного проверенного JSON в `.env.local` с правами 600. Для будущего Production подготовлен только частный файл `.local/subscriptions-final-20261107/seller-vercel.env`; окружение Vercel этим изменением не менялось. `BILLING_SELLER_NAME` для платежа должно совпасть с загруженным юридическим наименованием. Заполнение полей само по себе не разрешает публикацию и не включает оплату.

Локальный просмотр черновиков отдельно разрешается только при `NODE_ENV=development`, `BAZAAR_LEGAL_PREVIEW=1`, loopback Host и отсутствии признаков hosted deployment. Привязывать сервер следует к `127.0.0.1`. Metadata запрещает индексацию; ответы не кэшируются. Страница и middleware проверяют доступ независимо.

## Границы опубликованной оферты и оплаты

- Согласованная коммерческая сетка: 2 000 / 3 500 / 5 500 KGS за месяц, скидка 5% за шесть месяцев и 15% за год. База каждого тарифа — одна точка. Дополнительная точка доступна только двум старшим тарифам; общие пределы 1 / 5 / 15 точек. Единственный пакет запаса даёт +1 000 карточек и +2 пользователя; дополнения не открывают функции старшего тарифа. Числа и окончательная сумма перед оплатой берутся из общего каталога, а не рассчитываются текстом договора.
- Сроки — 1/6/12 календарных месяцев. Досрочное продление добавляет срок после действующего доступа. Повышение учитывает неиспользованную стоимость и сохраняет конец текущего срока; снижение планируется на следующий период после проверки вместимости. Изменение нескольких уже предоплаченных будущих периодов требует поддержки. Существующие договорённости, лимиты и пожизненные бесплатные условия сохраняются.
- Семидневный срок продления относится к новым договорам после оплаченного периода, не продлевает неоплаченный trial и не отменяет отдельную блокировку. По окончании сохраняются история, доступное чтение, получение данных и продление; создание/изменение операционных данных ограничивается согласно серверным правилам.
- Месячные AI, графические, почтовые и API-квоты обновляются помесячно даже при предоплате. Автоматических платных перерасходов нет.
- Оплата инициативная, разовая. Автосписания и обязательная привязка карты не обещаются: менеджер сообщил, что recurring на старте недоступен. Redirect браузера не подтверждает оплату; требуется проверенный серверный результат.
- Логотипы Visa/Mastercard/Элкарт сопровождаются пояснением: доступность конкретной карты подтверждается платёжной страницей FreedomPay. Наличие логотипа не означает активированный способ или одобрение мерчанта.
- Возвраты рассматривает исполнитель. Предлагаемые **10 рабочих дней на рассмотрение и 3 на передачу согласованного возврата** остаются проектом для утверждения; более короткий обязательный срок имеет приоритет. Это не обещание зачисления банком за 3 дня и не автоматический возврат в интерфейсе. Частичные возвраты, комиссии и споры требуют подтверждения договором провайдера.
- Подписка на Bazaar отделена от продаж товаров в магазинах клиентов. Продавец подписки и получатель KGS — ИП из `seller.ts`, а не магазин пользователя и не FreedomPay.

Для live-оплаты дополнительно нужны merchant ID/секрет, включённый live-режим и подтверждение активации провайдером. `paymentConfig.ts` проверяет реального продавца, точную версию оферты, опубликованные страницы и адрес `https://bazaar.kg/legal/offer` либо `https://www.bazaar.kg/legal/offer` в соответствии с выбранным origin. Vercel Preview/development, чужой домен, версия или продавец не проходят проверку. Настройки не менялись автоматически; ключи не запрашиваются в чате.

Политика конфиденциальности отражает фактические потоки: FreedomPay и данные счёта подписки, DeepSeek для текста, OpenAI для распознавания речи/изображений, инфраструктуру и почтового провайдера, разрешения устройств, права организаций и обращения по данным. Она не обещает локальную обработку всех данных, отсутствие внешних провайдеров или мгновенное удаление резервных копий.

## Что осталось от владельца и провайдера

1. Настроить `support@bazaar.kg` и проверить отправку/получение; телефон уже согласован.
2. Согласовать с FreedomPay и проверить юридически реальный публичный адрес для обращений без публикации домашнего адреса. Города самого по себе недостаточно считать вопрос решённым.
3. Предоставить паспорт в PDF и подтверждение владения `bazaar.kg` в согласованном защищённом канале. ИП, STI-025 и реквизиты сомового счёта уже включены в частный пакет.
4. Получить договор, подтвердить сроки KICB KGS, все комиссии, способы оплаты/зарубежные карты, полные и частичные возвраты/споры, допустимость предоплаты до года и максимального счета 204 000 KGS.
5. Утвердить окончательные тексты и договорные сроки возврата; проверить правовую квалификацию SaaS, налоговые/расчётные документы и переводы. Подготовленный проект не является заключением о полном юридическом соответствии.
6. Получить тестовый мерчант/API-доступ и указания по HTTPS callback. Секреты передавать через кабинет/защищённый канал.
7. После этого выполнить реальные тестовые сценарии: успех/отказ/отмена/истечение, потеря browser redirect, повторные и поздние callback, неверные подпись/сумма/валюта/организация, сверка статуса, однократное продление, 1/6/12 месяцев, доплаты, полные/частичные возвраты. Только затем допуск live и отдельная контрольная настоящая операция. До этого не утверждать, что эквайринг подключён.

## Частный пакет

`.local/freedompay-package-20261107.zip` содержит три неизменённых оригинала PDF, сообщение менеджеру, описание SaaS, согласованные суммы и чеклист. Каталог имеет права 700, файлы/ZIP — 600; `.local` исключён из git. Исходное свидетельство содержит домашний адрес и предназначено только для KYC провайдера. В `public/`, репозиторий или общедоступную ссылку этот пакет не переносить. Ничего не отправлено от имени владельца.

## Исходники и проверка

- `src/content/legal/seller.ts` — безопасные публичные значения по умолчанию; `src/server/legal/seller.ts` — серверный загрузчик подтверждённых реквизитов без домашнего адреса.
- `src/content/legal/{ru,kg,en}.ts` — четыре документа; `types.ts` — одинаковая структура переводов.
- `src/components/legal/legal-document.tsx` — общий шаблон на существующих Button/Card/Badge.
- `src/lib/legalPublication.ts`, `src/lib/legalPreview.ts`, middleware и маршрут — границы публикации.
- `src/app/privacy/page.tsx`, namespace `privacy` в сообщениях — политика.

Проверено отдельно без БД/провайдеров: **101 unit-тест** (границы публикации/preview, полнота RU/KG/EN, live-конфигурация, протокол платежа и privacy), **96 состояний локальных HTML** (12 черновых + 12 макетов публикации × desktop/mobile × light/dark), отсутствие горизонтального переполнения, работа ссылок/якорей, загрузка SVG и отсутствие домашних адресных полей/заглушек в макете публикации. Это проверка рендеринга и кода, не тест настоящего мерчанта. Общую сборку и регрессии всего приложения выполняет основной агент перед выпуском.

Воспроизводимый экспорт: `node --import tsx scripts/qa/legal-drafts-export.tsx`, затем `node --import tsx scripts/qa/legal-drafts-browser.tsx export`. Нужна собранная CSS приложения. Все HTML, скриншоты и `export.json` записываются в `.local/legal-drafts-20261104/`, русская копия без личных реквизитов — `docs/legal/drafts-ru.md`, заполненная частная копия — `.local/legal-drafts-20261104/drafts-ru.private.md`. Имена `review-published-*` — **только локальные макеты с явно синтетическим адресом для проверки компоновки**, не утверждённые публичные реквизиты. Экспорт не пишет в `public/`.

Изолированный сервер старого preview: `node scripts/qa/legal-drafts-runtime.mjs dev`, `http://localhost:3134/legal/offer`. Launcher отключает внешних провайдеров, не наследует API-ключи, в явном dev-preview читает только 13 серверных полей продавца и задаёт несуществующую локальную БД; он не предназначен для запуска магазина или реальной оплаты.
