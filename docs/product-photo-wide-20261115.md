# Фотопоиск: широкий ассортимент, 15 ноября 2026

Текущая связка PP-ShiTu + Faiss, PicoDet и PP-OCRv6 medium проверена без изменения
моделей, порогов и эталонов ELFBAR. Это поиск похожих кандидатов с обязательным
выбором человеком. Широкая проверка не подтверждает автоматическое определение SKU.

## Результат

В одном смешанном магазине 174 известных товара: 120 объявлений SOP и 54 класса
GroceryStoreDataset. Ещё 87 идентичностей отсутствуют в галерее. Всего 600 обычных
запросов и 119 дополнительных запросов с удалённым правильным товаром.

| Метрика | SOP: объявления | Grocery: классы товаров |
| --- | ---: | ---: |
| Известные запросы | 237 | 162 |
| Правильный первый до порога | 202 / 237 (85,2%) | 129 / 162 (79,6%) |
| Правильный в первых пяти до порога | 223 / 237 (94,1%) | 154 / 162 (95,1%) |
| Правильный первый в выдаче пользователю | 76 / 237 (32,1%) | 97 / 162 (59,9%) |
| Правильный среди показанных кандидатов, до восьми | 76 / 237 (32,1%) | 103 / 162 (63,6%) |
| Неправильный первый показанный кандидат | 0 / 237 | 9 / 162 (5,6%) |
| Пустая выдача для известного товара | 161 / 237 | 56 / 162 |
| Запросы отсутствующих товаров | 120 | 81 |
| Отсутствующий товар получил похожих кандидатов | 1 / 120 (0,8%) | 27 / 81 (33,3%) |

«Кандидаты» не означают подтверждённое наличие сфотографированного товара. При
отсутствующем товаре любой предложенный сосед считается таким случаем, даже если
интерфейс честно называет его похожим. Эти доли нельзя объединять в одну «точность SKU»:
в SOP метка — объявление продавца, в Grocery — класс, иногда сорт фрукта.

В сложных парах, выбранных только по сходству эталонов, правильный кандидат показан
в 19/47 запросов SOP и 55/72 Grocery. После удаления всех фотографий правильного
товара кандидаты остались в 0/47 и 25/72 запросов соответственно. Среди отсутствующих
классов Grocery, имеющих известного соседа в той же крупной категории, кандидаты
появились в 15/42 запросов. Полные таблицы категорий находятся в
[summary.json](benchmarks/product-photo-wide-20261115/summary.json).

Примеры путаницы: Royal Gala → Peach, Lemon → Lime, Nectarine → Peach,
Yoggi Vanilla Yoghurt → Yoggi Strawberry Yoghurt, Orange Bell Pepper → Yellow Bell Pepper.
Правильный сорт/вкус нельзя выводить из похожего цвета и формы. Для SOP основной
предел — пропуски: правильный сосед часто есть в исходном ранжировании, но не проходит
действующий порог 0,68. Порог в этой работе не снижался.

## Данные и независимость

- [Stanford Online Products](https://cvgl.stanford.edu/projects/lifted_struct/), публичное
  зеркало [nyris/stanford-online-products-v1](https://huggingface.co/datasets/nyris/stanford-online-products-v1),
  revision `24a1b9b8ec6c0b1fc4dd324f24b2d829413a6c69`, только официальный test split.
  Двенадцать категорий: велосипеды, шкафы, стулья, кофеварки, вентиляторы, чайники,
  лампы, кружки, диваны, степлеры, столы и тостеры. Для каждой — 10 известных и 5
  отсутствующих объявлений; по два эталона и два других снимка. Выбор детерминирован
  внутри двух окон по 100 строк около середины категории; это не равномерная выборка
  всего SOP. Названия карточек технические: `SOP category listing_id`; настоящих
  названий продавцов нет, поэтому богатые товарные метаданные для OCR здесь не проверены.
- [GroceryStoreDataset](https://github.com/marcusklasson/GroceryStoreDataset), revision
  `fc80ba90f803d79d0383df52c5a4ac5de99ff6fc`. Все 81 fine class: 54 известных,
  27 отсутствующих. В gallery — iconic и два train-снимка, в запросах — три test-снимка
  класса из официального разбиения. Есть фрукты, овощи и похожие упаковки молока,
  йогуртов и соков; естественные снимки сделаны в магазинах, с фоном и изменениями ракурса.
  В использованном `classes.csv` 43 уникальных coarse ID, несмотря на число 42 в README.

Протокол и seed зафиксированы до инференса в
[product-photo-wide-policy.json](../scripts/qa/fixtures/product-photo-wide-policy.json).
ELFBAR не входит ни в галерею, ни в запросы. Нет синтетических «фото в руке» или
преобразований одного эталона, выдаваемых за независимые фотографии.

Три SOP-запроса исключены из-за полного совпадения байтов или декодированных RGB-пикселей
с галереей; у одного объявления после этого нет запросов. Получились 237 известных
запросов по 119 объявлениям. Между разными товарами точных дубликатов эталонов нет.
Две пары эталонов одного объявления идентичны: 402 записи фотографий дают 400
уникальных источников в приложении с адресацией файлов по содержимому. Отчёт не удаляет
эти записи задним числом и не меняет выборку по результатам поиска.

Возможны близкие снимки внутри объявления и пересечение публичных фотографий
с предобучением сторонних моделей. Нельзя считать эту проверку гарантированно
незагрязнённым тестом новых пользовательских фото. Кодовая лицензия набора сама по
себе не устанавливает права на каждую фотографию; изображения не включены в git,
не используются в production и не распространяются с отчётом.

## Проверка через Bazaar

В явно изолированном локальном магазине «Открытый ассортимент — фото (тест)»
созданы 174 тестовые карточки. Все 402 изображения прошли существующий upload API;
worker подготовил 400 уникальных источников без ошибок. Цены и продажи не выдумывались,
финансовые и складские операции не создавались.

48 заранее детерминированных запросов прошли настоящий authenticated API приложения:
по одному известному и отсутствующему на категорию SOP, по четыре на семейство Grocery.
Все ответы HTTP 200; списки кандидатов совпали со стендом **48/48**. Для SOP правильный
показан в 4/12 известных запросов, для Grocery — 6/12. Среди отсутствующих кандидаты
получили соответственно 0/12 и 2/12. Это подвыборка, а не замена полной таблицы выше.
Пустой другой магазин вернул пустой список. Каталог и кэш признаков до/после поиска
совпали; исходные организации, пользователи, магазины и товары сохранились даже после
возобновления прерванной загрузки. Изоляция ролей/организаций дополнительно покрыта
существующими интеграционными тестами фотопоиска с PostgreSQL.

## Время и ресурсы

На локальном Apple M4, один поток вычислений: SOP p50/p95 ≈ 0,67/1,84 с,
Grocery ≈ 0,81/3,41 с. Выборочный суммарный максимум RSS процесса моделей и
дочернего Faiss — 1889 MiB. Это время pipeline без HTTP и первоначальной индексации.
Одновременно выполнялись другие проверки; числа не являются оценкой пропускной
способности production. Нагрузочный тест и Linux на целевом сервере ещё нужны.

## Расположение кнопок и телефон

Два входа: кнопка с подписью в фильтрах страницы товаров и компактная камера справа
от общего поля «Сканировать или искать». На телефоне поле и камера расположены
отдельной строкой под заголовком, без вытеснения профиля, подсказок и меню. Отдельная
кнопка на странице входа в кассу удалена; полноэкранная продажа `/pos/sell`, где нет
общей шапки приложения, не получила дополнительного входа.

Повторно используются существующее окно, загрузка, явный выбор магазина и кандидата.
Для сотрудника без доступа к карточкам выбор остаётся просмотром. Никакой проверки
платного тарифа или расхода AI-кредитов нет. Список магазинов ограничен существующими
правами; при его ошибке в окне доступен повтор. При смене пользователя/организации
или страницы временное фото сбрасывается. Крупный редактор рамки загружается по запросу.

В собственном фоновом браузере проверены desktop 1280 и mobile 390/320: камера 44×44
на телефоне, отсутствие горизонтальной прокрутки, окно, выбор магазина, загрузка,
ожидание, прокрутка результата и переход к выбранной Banana. В кассе остался один
общий вход. Найдено и исправлено предупреждение Select при первом выборе магазина;
после повторного открытия нового предупреждения не было. Живую камеру на физическом
телефоне эта проверка не заменяет.

## Воспроизведение и доказательства

Нужна локальная среда моделей из `services/product-photo-search/README.md`.
Из корня репозитория, без клиентских БД и без платных провайдеров:

```sh
PY=.local/product-photo-search/runtime/venv/bin/python
$PY scripts/benchmarks/product-photo/prepare-wide.py --download
node scripts/qa/prepare-wide-photo-inputs.mjs
$PY scripts/benchmarks/product-photo/wide.py
node --import tsx scripts/qa/score-wide-photo-search.ts
```

Подготовка требует публичной сети и доступности закреплённых источников. Без
`--download` проверяются локальные исходники и их хэши. `wide-photo-api.mjs` дополнительно
проверяет конкретные disposable marker, БД, организацию и адрес тестового приложения;
его нельзя перенаправлять на рабочую инфраструктуру. QA-пароль берётся только из среды.

В [audit.json](benchmarks/product-photo-wide-20261115/audit.json) — хэши, исключения,
дубликаты и результат API-сверки. Рядом — полные `inputs`, `native`, `scored`, `api`
в gzip и выбранные сложные пары; `gzip -dc FILE.json.gz` раскрывает обычный JSON.
Файлы фотографий и моделей в репозиторий не добавлялись. Порог, модель и механизм
принятия кандидатов остались прежними. Дальнейшая подготовка к main описана в
[записи проверки ветки](playground-main-readiness-20261115.md).
