## 21: managed image source

Original dataflow: an authenticated ADMIN/MANAGER supplies query `url` → `resolveManagedSourceUrl` parses an HTTP(S) URL → the code accepts `isManagedProductImageUrl(parsed.pathname)` → `fetch` uses the original absolute URL and follows redirects by default. The storage predicate (`productImageStorage.ts:868–888`) recognizes string prefixes, not trusted network origins. Consequently `http://127.0.0.1/uploads/imported-products/probe.jpg` or an attacker-controlled public host with the same path passes the old guard. Authentication limits who can reach the endpoint but does not constrain destination hosts.

Fix: replace pathname-only acceptance with an exact configured application/storage origin and managed path policy. Production does not trust the request Host as an additional application origin. The request-origin fallback is limited to nonproduction when no configured application origin exists. Storage credentials, nonstandard remote ports and lookalike hostname prefixes are rejected. Redirects repeat the policy and public-address checks. Known local uploads are read from the uploads directory directly, avoiding any loopback-network exemption. Legacy `retails/` sources resolve against the configured storage base, including its subdirectory.

## 27: product image export

Original dataflow: product image input accepts nonempty strings → `resolveProductImageUrl` normalizes HTTP(S), but deliberately retains original URLs when a remote import/download fails (`productImageStorage.ts:983–1021`) → `resolveIncomingProductImages` persists that result (`products.ts:1833–1865`) → `exportProductImagesData` returns it after organization/store access checks (`products/read.ts:2254–2308`) → the serializer only excludes data URLs and excessive string length (`serializers.ts:102–113`) → export directly fetches the URL, following redirects. Thus a private URL rejected by the importer can remain stored and later reach a less protected export sink. Merely being database-sourced or tenant-scoped does not sanitize the network destination.

Fix: export uses the same safe network transport for arbitrary legitimate public imported-photo URLs; it is not restricted to Bazaar's storage CDN. Private, mapped and reserved destinations are skipped without aborting the rest of the ZIP workflow. Public redirects remain supported, with independent checks at each hop. Existing local uploads remain readable with canonical-path and realpath containment; traversal and symlink escapes are rejected. ZIP size controls, progress events, organization/user download ownership and one-time download behavior are retained.

## Shared transport proof

`src/server/services/productImageFetch.ts` resolves every candidate's complete DNS answer set, rejects it if any answer is unsafe, then pins only the validated addresses through the native HTTP(S) connection's custom lookup. The original hostname remains in the URL for Host, SNI and certificate verification. Agent reuse is disabled for these calls. This avoids the separate-validation/second-DNS-resolution gap of a normal precheck followed by unrestricted `fetch`. Native HTTP does not automatically follow redirects. The application explicitly handles at most three redirects, rechecking policy and addresses at every hop. Abort signals bound DNS, connection and stream lifetime. Both content-length and actual streamed byte counts are bounded. No new dependency is required.

IPv4 and IPv6 block lists are separate because Node's IPv4-mapped matching can otherwise accidentally reject every IPv4 address. Controls include IPv4-mapped/NAT64 and compatible IPv6, local/site-local/link-local ranges, documentation/benchmark/discard/special prefixes. The four extra IPv6 prefixes were checked against the [IANA registry](https://www.iana.org/assignments/iana-ipv6-special-registry): `100:0:0:1::/64`, `2001:2::/48`, `3fff::/20`, `5f00::/16`. Deprecated site-local `fec0::/10` is also denied (RFC 3879).

## 29: public catalogue image proxy

The current endpoint already requires exact operator-configured application or R2 origins and permitted path prefixes (`getAllowedSources` / `resolveAllowedManagedUrl`, lines 104–201). It rejects credentials, non-HTTP(S) schemes and nondefault ports. `assertPublicHost` rejects local names, literal private/reserved IPs and any private DNS answer before I/O. `fetchAllowedImage` uses manual redirects, repeats hostname checks before every hop and applies the same origin/path policy to each Location header (lines 249–311). Response MIME, size and timeout bounds are also present.

Inference: CodeQL follows user input through the custom resolver and does not recognize this destination policy. Under the documented assumption that server-configured application/storage domains are trusted, users cannot select an arbitrary DNS authority or redirect outside that allowlist. The endpoint still performs separate DNS checking and fetching rather than connection pinning; this review does not claim that it withstands a compromised operator domain/configuration. No direct attacker-selectable-host SSRF was demonstrated in this endpoint. Its existing security suite was read during triage; the root subsequently reran it with 44 passing tests (`public-image-final.json`). No dismissal was performed.
